# 1. Обновленная диаграмма C4 контейнеров
Новые сервисы партнёра:

- Интеллектуальный домофон: классический видеодомофон + автооткрытие по распознаванию лица разрешённого пользователя.

- Интеллектуальный шлагбаум: управление шлагбаумом + автооткрытие по распознаванию госномера автомобиля из разрешённого списка.

Сервисы должны быть доступны в текущем мобильном приложении собственника.

# 2. Требования к внешним интеграциям

### 1) Требования к безопасности

- Шифрование трафика: все каналы HTTPS (TLS 1.2+).
- Изоляция секретов: ключи/токены интеграций хранятся в хранилище секретов; доступ только сервис-аккаунтам.
- Журналирование и аудит: фиксировать все команды «открыть/отклонить», входящие события распознавания и административные изменения.
- Минимизация данных: PropDevelopment не обрабатывает биометрические шаблоны/изображения лиц и распознанные кадры; в своей БД хранит только идентификаторы пользователей/авто и статусы доступа.

### 2) Аутентификация и авторизация

- Мобильное приложение → PropDevelopment: аутентификация через существующую схему приложения; авторизация по ролям/правам собственника внутри бэкенда.
- PropDevelopment → Партнёр: сервисная аутентификация (например, OAuth 2.0 Client Credentials) от имени интеграционного контейнера; авторизация на уровне API‑ключей/ролей партнёра.

### 3) Организация взаимодействия

- Схема вызовов: мобильное приложение вызывает только внутренний API; интеграции с партнёром выполняет контейнер Smart Home Integrator.

    Модель данных:
    - у PropDevelopment: user_id, access_profile_id, список разрешённых авто (номер), статус доступа, история событий;

    - у Партнёра: собственные идентификаторы биометрии/авто.
